## System design

**Функциональные требования:**

1) Посты:
- Пользователь может создать пост о путешествии:
  - добавить текстовое описание до 300 символов
  - прикрепить до 10 фотографий
  - указать место путешествия из заранее заданного справочника мест: город/страна/POI
  - опубликовать пост в профиле
  - видео не поддерживаются в MVP
- Пользователь может редактировать и удалять свои посты
- В MVP все посты публичные

2) Оценка постов:
- Пользователь может поставить не более одного лайка на один пост
- Пользователь может убрать лайк к посту
- Пользователь может видеть количество лайков у поста

3) Комментарии к постам:
- Пользователь может оставить комментарий к посту
- Пользователь может удалить свой комментарий
- Пользователь может просматривать список комментариев к посту в обратном хронологическом порядке
- Комментарии в MVP являются плоскими, ответы на комментарии не поддерживаются
- Список комментариев поддерживает пагинацию

4) Подписка:
- Пользователь может подписаться на другого пользователя
- Пользователь может отписаться от другого пользователя
- Пользователь может просматривать список своих подписок
- Пользователь может просматривать список своих подписчиков
- Подписка в MVP применяется сразу и не требует подтверждения

5) Ленты:
- Пользователь может просматривать профиль другого пользователя и его публичные посты в обратном хронологическом порядке
- Пользователь может просматривать свою домашнюю ленту, состоящую из постов пользователей, на которых он подписан
- Домашняя лента сортируется в обратном хронологическом порядке
- Бесконечная прокрутка
- Размер страницы ленты 10 постов
- Показываем в ленте первое превью фото поста
- Мгновенное появление нового поста в ленте не требуется в MVP, задержка в несколько секунд допустима

6) Поиск мест для путешествий:
- Поиск выполняется по заранее заданному справочнику мест
- Пользователь может просматривать список популярных мест
- Пользователь может открыть страницу места и посмотреть посты, связанные с этим местом
- Популярность места определяется на основе пользовательской активности: количества постов и лайков

7) Профиль пользователя:
- Пользователь имеет профиль: имя, аватар, описание, страна/город
- Пользователь может просматривать профиль другого пользователя
- Профиль пользователя содержит список его публичных постов

8) Авторизация:
- Пользователь может зарегистрироваться в системе
- Пользователь может авторизоваться в системе
- Только авторизованный пользователь может создавать посты, ставить лайки, комментировать и подписываться

**Out of scope для MVP**

- Видео в постах
- Stories / временные публикации
- Личные сообщения и групповые чаты
- Приватные аккаунты и приватные посты
- Push-уведомления и email-уведомления
- Алгоритмическая рекомендательная лента
- Геолокация в реальном времени
- Карта с отображением постов
- Полнотекстовый поиск по текстам постов и комментариев
- Поиск пользователей и поиск по хэштегам
- Древовидные комментарии и ответы на комментарии
- Сохранение постов в избранное и коллекции
- Синхронизация черновиков между устройствами

**Нефункциональные требования:**

1) DAU
- Ожидаемая нагрузка через год: 10 000 000 DAU
- Рост аудитории в течение первого года считается линейным

2) Аудитория
- Основная аудитория находится в странах СНГ
- Система должна обеспечивать приемлемую задержку для пользователей из этого региона
- Глобальная мульти-региональная архитектура не требуется

3) Хранение данных
- Пользовательский контент — посты, фотографии, комментарии — должен храниться долговременно (пользователям важен архив воспоминаний из путешествий)
- Пользователь может удалить свой контент
- Система должна обеспечивать защиту от потери данных через репликацию и резервное копирование
- Кэши, индексы поиска и предрасчитанные ленты могут быть восстановлены из основных данных

4) Допущения по активности пользователей:
- 10% DAU создают 1 пост в день
- В среднем пост содержит 5 фотографий
- Максимум — 10 фотографий на пост
- Каждый DAU просматривает 10 постов в день
- Каждый DAU ставит 5 лайков в день
- 20% DAU оставляют 2 комментария в день
- 10% DAU подписываются на 2 пользователей в день
- Каждый DAU выполняет 5 поисковых запросов по местам в день

5) Лимиты:
- Максимум фотографий в одном посте: 10
- Среднее количество фотографий в посте для расчёта: 5
- Максимальный размер исходной фотографии: 10 MB
- Средний размер оптимизированной фотографии для просмотра: 300 KB
- Максимальная длина описания поста: 300 символов
- Максимальная длина комментария: 500 символов
- Размер страницы ленты: 10 постов
- Размер страницы комментариев: 20 комментариев
- Максимальное число подписок на пользователя: 10 000
- Места заранее заданы в справочнике, автоматическое определение места по координатам в MVP не поддерживается

6) Сезонность
- В летний сезон и праздничные периоды ожидается рост активности на 30–40%
- Для расчётов пиковой нагрузки используем seasonal factor = 1.4
- Для оценки пиковой нагрузки дополнительно используем daily peak factor = 3
- Итоговый peak multiplier = 3 * 1.4 = 4.2

7) Временные ограничения:
- Открытие ленты: 1с без учета загрузки изображений
- Получение комментариев: 1с
- Публикация поста metadata: 1с без учета загрузки фотографий
- Поиск мест: 1с
- Загрузка фотографий может занимать дольше и выполняется отдельно от создания metadata поста
- Новый пост отображается автору сразу после успешной публикации metadata
- В лентах подписчиков новый пост может появиться с задержкой до 60с
- Пользователь, поставивший лайк, видит изменение сразу
- Остальные пользователи могут увидеть обновлённый счётчик лайков с задержкой до 300с
- Пользователь, оставивший комментарий, видит его сразу
- Остальные пользователи могут увидеть новый комментарий с задержкой до 60с
- Новая подписка отображается подписавшемуся пользователю сразу
- Счётчик подписчиков у пользователя может обновляться с задержкой до 300с

8) Доступность
  - Целевая доступность основных read-сценариев: 99.9%
  - Целевая доступность write-сценариев: 99.5%

**Оценка нагрузки:**

| Подсистема | Операций в день | Avg RPS | Peak RPS с x4.2 |
| :--- | :---: | ---: | ---: |
| Создание постов | 1_000_000 | 10 | 40 |
| Загрузка фото | 5_000_000 | 50 | 200 |
| Просмотр постов | 100_000_000 | 1000 | 4000 |
| Лайки | 50_000_000 | 500 | 2000 |
| Комментарии | 4_000_000 | 40 | 160 |
| Подписки | 2_000_000 | 20 | 80 |
| Поиск мест | 50_000_000 | 500 | 2000 |

**Оценка трафика:**

- Средний размер исходной фотографии при загрузке: 3 MB
- Средний размер оптимизированной фотографии для отображения: 300 KB
- В ленте на один пост отображается 1 превью-фото
- Средний metadata payload поста: 2 KB
- Средний комментарий: 500 bytes

*Upload трафик:* 5 000 000 фото/day * 3 MB = 15 TB/day
*Download трафик в ленте:* 100 000 000 просмотров постов/day * 300 KB = 30 TB/day

*Средний upload throughput:* 15 TB/day ≈ 150 MB/s
*Пиковый upload throughput:* 174 MB/s * 4.2 ≈ 731 MB/s

*Средний download throughput:* 30 TB/day / 86 400 ≈ 300 MB/s
*Пиковый download throughput:* 347 MB/s * 4.2 ≈ 1.46 GB/s
